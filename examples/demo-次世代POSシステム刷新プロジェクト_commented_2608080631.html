PROJECT NOVA — POS SYSTEM RENEWAL

次世代POSシステム刷新プロジェクト
「Project NOVA」提案資料

全国128店舗の現行POS基盤（保守期限 2027年3月）を刷新し、レジ待ち時間の短縮と在庫データのリアルタイム連携を実現する。
本資料は経営会議に対し、投資判断に必要な効果・費用・体制・リスク・依頼事項を整理したものである。
2026.08.08

3.4億円を投じて全128店舗のPOSを刷新し、レジ待ち時間を40％短縮する
本件の結論・根拠・依頼と、達成を判定する4指標を1枚に集約した。詳細は次頁以降で順に説明する。

保守期限まで残り19か月 ― 2026年9月の決裁が、2027年3月に間に合うかどうかの分岐点になる

背景
現行POS「Retail-Core POS Ver.3」は導入13年目で、保守契約が2027年3月末に満了する。ピーク時のレジ待ちは平均4.2分、端末停止は年37件と増加傾向にある。
結論
クラウド型POS基盤「NOVA-POS」へ全128店舗を移行し、2027年1月までに切替完了。レジ待ちを4.2分→2.5分とする。
根拠
  1. 保守終了後は部品調達・障害復旧の担保が無い（社内保守記録・2025年度で年37件の端末停止）
  2. 待ち時間の主因はスキャンと決済の端末分離であり、統合で1件あたり32秒短縮できる（店舗調査・2026年5月）
  3. 年間運用費が8,400万円→6,800万円に低減し、約4年で初期投資を回収できる
依頼
初期投資3.4億円の下期補正予算への計上と、ベンダーとの契約締結（2026年9月15日まで）の承認。

成否は4指標で判定する ― いずれも既存の計測手段で追え、店舗に追加作業は生じない

PROJECT NOVA / POS SYSTEM RENEWAL P.2
NO.01 — 現状と課題構造 【 必須 】
レジ待ちの主因は台数不足ではなくスキャンと決済の端末分離にあり、端末統合で解消できる
現状のどこに問題があるかを対置で示し、待ち時間の発生箇所を要因分解で特定した。

分断された3つの業務を、NOVA-POSによる一体運用へ転換する

現状（As-Is）
  • スキャン端末と決済端末が分離し、金額の二度打ちが発生している
  • 在庫は日次バッチ更新のため、店舗間の在庫偏在に当日対応できない
  • 決済手段は9種類にとどまり、QRコード決済に未対応
あるべき姿（To-Be）「NOVA-POS」
  • スキャン・決済・レシート発行を1台のタブレット型端末に統合する
  • 販売と同時に在庫を更新し、店舗間の検索・取り寄せをレジ画面から行う
  • QRコード決済3社を加えた15種類に対応する

レジ増設では解決しない ― 1件あたりの会計処理そのものを短縮しなければ待ち時間は減らない

  • POS本体・周辺機器の全台リプレースレジ端末・バーコードリーダー・レシートプリンタ／128店舗 約640台

  • ECサイトとの在庫連携次期フェーズで別途見積

※ 対象外の項目が本フェーズで必要になった場合は、変更管理プロセスにより別途見積・スケジュール協議を行う。
この線引きにした理由
  • 会計システムは2024年に更改済みで、耐用年数を4年残している
  • EC連携を含めると期間が+6か月となり、保守期限に間に合わない
  • 会員基盤はPOS刷新と依存関係が無く、切り離しても手戻りが生じない
範囲変更が起きた場合の扱い
  • 追加要望はPMO定例で受け付け、影響度を見積ったうえで本会議へ上程する
  • 展開開始（26/Q4）以降の範囲追加は、原則として次期フェーズへ送る
  • 変更に伴う増額は0.1億円までPMO長の決裁、超過分は本会議の決議とする
対象外項目の見込み規模
  • EC在庫連携：概算0.6億円／6か月（次期フェーズ）
  • 会員基盤刷新：概算1.1億円／9か月（2028年度以降）
  • いずれも本件の設計を前提に接続できる構成としておく
NOTE
対象外3項目は「やらない」ではなく「今回はやらない」。次期フェーズの検討開始は2027年度上期を想定

01 MIGRATION POLICY
移行の考え方
後戻りできる規模で確かめる
128店舗を一度に切り替えず、まず10店舗で効果とデータ精度を実測する。基準を満たさなければこの時点で計画を止め、原因を潰してから展開に入る。
並行稼働の設計
  • 各店で1週間は旧POSを撤去せず残し、障害時に即時切り戻せる状態を保つ
  • 並行稼働は最長4週間を上限とし、超える場合は本会議へ再上程する
  • データ移行は展開日の2週間前までに完了させ、差分のみ当日反映する
切り戻しの判断基準
  • 売上データの欠落・二重計上が1件でも発生した場合、当該店を即時切り戻す
  • 同時に3店舗以上でレジ停止が発生した場合、展開そのものを中断する

02 RATIONALE
この分担にした理由
受入判定を現場に置く
受入判定の説明責任を情シスではなく店舗運営部に置くことで、現場が使えないものが通らない構造にする。判定基準は前頁の教育・品質チームが事前に整備する。
データ移行の判断を一元化
  • 移行精度99.9％の可否判断は情シスに集約し、店舗ごとの個別判断を認めない
  • ベンダーは実行（R）に徹し、合否の説明責任は持たせない
Aを1名に限る運用
  • 各工程のAは1組織1名。合議で決めた場合もAが単独で説明責任を負う
  • AとRが同一組織になる工程は置かない（自己承認を避ける）
